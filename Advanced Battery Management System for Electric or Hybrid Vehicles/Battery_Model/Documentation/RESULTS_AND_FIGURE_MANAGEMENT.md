# Results and Figure Management

## Purpose

All demonstration scripts that generate figures must save their outputs under the canonical `Battery_Model/Results` directory. This keeps presentation and report evidence organized, reproducible, and separate from source code.

## Shared export function

Use `saveBMSFigure(fig, projectRoot, category, baseName)`.

The helper:
- creates the requested category folder when it does not exist;
- exports a 300 dpi PNG for reports and presentations;
- saves an editable MATLAB `.fig` file;
- prints the absolute output paths in the Command Window;
- overwrites files with the same names on a rerun.

Example:

```matlab
saveBMSFigure(fig, projectRoot, ...
    'Cell_Model/ECM/1RC', ...
    'ECM_1RC_Terminal_Voltage');
```

## Results taxonomy

| Module | Category folder | Current demonstration output |
|---|---|---|
| Cell model / 1RC ECM | `Results/Cell_Model/ECM/1RC/` | Terminal voltage, OCV, SOC |
| Cell model / dynamic ECM | `Results/Cell_Model/ECM/Dynamic/` | Current profile, terminal voltage, OCV, SOC |
| SOC / Coulomb counting | `Results/SOC/CoulombCounting/` | Constant, step and pulse SOC comparison |
| Thermal model | `Results/Thermal/` | Cell temperature rise |

Future figure-generating demonstrations must use the same helper and add their output category to this document. Pack scripts that currently produce text/table output do not create figures and therefore have no figure files to save.

## Naming convention

Use descriptive names in this order:

`<Module>_<Model>_<Quantity>_<Scenario>.<extension>`

Examples:
- `ECM_1RC_Terminal_Voltage.png`
- `ECM_Dynamic_Current_Profile.png`
- `SOC_CoulombCounting_CurrentProfile_Comparison.png`
- `Thermal_Cell_Temperature_Rise_2A_300s.png`

Avoid ambiguous names such as `Figure1.png`, `plot2.fig`, or `final.png`.

## Reproducibility metadata

Every demonstration should print or record the operating conditions needed to interpret its plots: cell/model identifier, current profile, current range, initial SOC, duration, time step, and relevant thermal/pack assumptions.

A plotted simulation is not experimental validation. Record whether the input profile is synthetic or measured, and identify the data source where available.

## Current modelling caveats

- The dynamic current profile generated by `driveCycleCurrent` is synthetic and is not an official WLTP or UDDS trace. In the single-cell dynamic ECM demonstration it is scaled by 0.1 to keep the current within the configured provisional 5 A discharge limit.
- The thermal demonstration uses 2 A for 300 s, within the configured provisional 5 A discharge limit.
- The 5 A limit itself is a provisional project assumption and must be verified before hardware use.
- The OCV lookup data provenance and test conditions remain unverified.
- Thermal parameters remain provisional; the temperature plot is a model simulation, not a measurement-based validation.
- The 1RC and dynamic ECM outputs have not been validated against independent measured cell-voltage data.

## How to rerun

From the canonical `Battery_Model` folder:

```matlab
setupProject();
run('Tests/testECM.m');
run('Tests/testDynamicECM.m');
run('Tests/testSOC.m');
run('Tests/testTemperature.m');
```

Inspect the Command Window for the exact saved paths. Re-running a demonstration overwrites outputs with the same filenames. Back up any result that must be preserved before changing the simulation conditions.
